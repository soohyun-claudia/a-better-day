## 3. D02의 초 절삭과 120분 경계 분석

- 확정 정책은 **남은 시간 차이의 초를 버려 분으로 판단**하는 것이다.
  예를 들어 119분 59초는 119분이며 urgent=true다. 정확히 120분은 urgent=false다.
- 현재 `src/main/java/com/abetterday/task/service/DueLabeler.java:70-71`은
  마감 시각과 현재 시각을 각각 `truncatedTo(MINUTES)`로 절삭한 뒤 `:72`에서 차이를 계산한다.
  두 시각 각각의 절삭과 시간 차이의 절삭은 서로 같지 않다.
- 현재 초가 마감 초보다 크면 남은 시간이 실제 절삭값보다 1분 커질 수 있다.
  예: 12:00:01 → 14:00:00은 실제 119분 59초지만 코드에서는 12:00 → 14:00의 120분이 된다.
- `:75`의 `diff < 120` 비교 연산 자체는 올바르다. 비교 연산을 `<=`로 바꾸는 수정은 필요하지 않다.
  원인은 비교에 들어가는 diff의 계산 방식이다.
- 위 실패 1·2는 이 계산 오류가 urgent 경계를 넘어가게 하는 사례다.
  실패 3~7은 같은 원인으로 표시 분만 1분 커지는 사례다. 동일한 결함 R01로 묶는다.
- 기존 정확히 120분·119분 테스트는 통과했다.
  추가 120분 59초·120분 1초·정확히 0초·59초 남음의 동일 분 입력도 통과했다.
  일부 경계가 통과하더라도 서로 다른 초가 있는 7개 실패를 상쇄하지 않는다.

수정 권장: Claude가 원래 시각들의 차이를 먼저 구한 뒤, 그 남은 시간의 초를 버린 분을
라벨 접미어와 urgent 계산에 공통으로 사용하도록 수정한다. 표시용 HH:mm 서식 때문에 판단용 시각을 절삭하지 않는다.
이번 재분류는 기존 54개 범위이며 음수의 초 단위 처리 등에 대한 새로운 정책을 추가로 정하지 않는다.

## 4. D03의 문구와 우선순위 분석 및 기대값 정정

- 문서 근거: `.kiro/specs/spec-1-task-core/requirements.md:166`, `design.md:104,378`은
  날짜 전용 오늘 마감의 실제 문구를 “오늘 중”으로 정의한다.
- 확정 우선순위: 지남 → 오늘 → 내일 → 이번 주 일요일 → 일반 날짜.
  일요일 당일에도 오늘 규칙을 먼저 적용하고 문구는 “오늘 중”을 유지한다.
- 코드 근거: `DueLabeler.java:53-54`의 오늘 분기가 `:59-60`의 일요일 분기보다 먼저다.
  실제 반환 문구도 “오늘 중”이므로 구현에 문구 오류나 우선순위 오류가 없다.

### 음수 초 처리와 ‘지금 마감’ 추가 확인

- 수정 구현은 `Duration.between(now, target).toMinutes()`를 사용한다. `Duration.toMinutes()`는 음수도 0 방향으로 소수 분을 버린다.
  따라서 마감 후 1~59초는 `diff == 0`이 되어 `urgent=true`와 `지금 마감`으로 표시된다.
- 현재 명세는 `diff == 0`을 “지금 마감”으로 정의하고, 음수 분 지남은 `N분 지남`으로 정의하지만,
  마감 후 1분 미만을 별도로 정의하지 않는다. 이 구간을 “지금 마감”으로 볼지 “1분 지남”으로 올림할지는 추가 정책 확인이 필요하다.
  이번 리뷰에서는 사용자가 확정한 “초를 버린 분 값”에 따른 현재 동작을 결함으로 확정하지 않았고, 프로덕션 코드도 수정하지 않았다.
- 마감 후 60초 이상은 `diff < 0`이 되어 기존 분·시간·일 단위 지남 문구로 처리되며, 기존 테스트가 이를 통과했다.
