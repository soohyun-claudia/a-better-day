# Kiro Spec 진행 계획과 프롬프트

steering 파일이 아니라 참고용 문서예요. `.kiro/steering/`에 넣지 말고 `docs/`에 두세요.

## Spec 분할

MVP 완료 기준은 product.md의 "화면 요소 체크리스트"를 전부 채우는 것입니다. 모든 spec은 Requirements-First로 시작합니다.

| Spec | 범위 |
|---|---|
| 1. 기반 + task 핵심 | docker-compose PostgreSQL, Flyway, task API(생성·조회·상태 전환), 상단 바, 오늘 할 일·한 일·하고 싶은 일 패널(표시, 체크·▶·승격, 빠른 추가) |
| 2. task 편집 | 할 일·하고 싶은 일의 추가·수정·삭제 모달, 카테고리 지정, 우선순위 지정 |
| 3. event + 오늘 일정 | event API(추가·수정·삭제), 오늘 일정 패널(다음 일정 카드, 타임라인, 현재 시각선), 일정 편집 모달 |
| 4. 하단 바 + 마무리 | 이번 주 완료, 요일별 완료 막대, 내일 일정, 자동 갱신 점검, 해상도 대응, 백업 스크립트, 체크리스트 최종 점검 |

---

## Spec 1 프롬프트 (Kiro에서 Spec 생성 후 그대로 붙여넣기)

```
개인 업무용 상시 대시보드의 첫 번째 기능으로, 프로젝트 기반과 task 핵심 기능을 만들고 싶어.
steering 문서(product, tech, structure, frontend-conventions, db-conventions)의 규칙을 따라줘.
화면 디자인은 docs/ 폴더의 프로토타입 캡처 이미지를 기준으로 하고, product.md의 "동작 규칙"과 "화면 요소 체크리스트"를 따라줘.

[범위]
1. 로컬 개발 환경
   - docker-compose.yml로 PostgreSQL 실행 (named volume, .env로 접속 정보 분리)
   - Spring Boot가 DB에 접속하고 Flyway로 V1 마이그레이션 적용
2. task 도메인 (WISH / TODO / DOING / DONE)
   - 생성, 목록 조회(상태별) API
   - 상태 전환: 체크하면 DONE(done_at 기록), ▶ 하면 DOING(동시에 1개만, 기존 DOING은 TODO로 되돌림), WISH → TODO 승격
3. 화면 (정적 index.html, Bootstrap 5.3.8, 바닐라 JS)
   - 상단 바: 시계, 날짜·요일·연도, 지금 집중할 일, 오늘 진행률
   - 가운데 "오늘 할 일" 패널 (최대 7개 표시, DOING 강조, 우선순위·마감 색 구분, 체크·▶ 버튼, 빠른 추가 입력창)
   - 오른쪽 위 "한 일" 패널 (오늘 완료한 항목 + 완료 시각)
   - 오른쪽 아래 "하고 싶은 일" 패널 (카테고리 태그, 4개 표시, 승격 버튼)
   - 왼쪽 일정 패널과 하단 바는 이번 spec 범위가 아니므로 자리만 잡아둬
4. 하고 싶은 일은 Spec 2 전까지 화면에서 추가할 수 없으니, 개발용 샘플 데이터를 넣는 방법을 제안해줘

[이번 spec에서 제외]
수정·삭제·하고 싶은 일 추가·카테고리·우선순위 지정(Spec 2), event와 오늘 일정 패널(Spec 3), 하단 바(Spec 4), 반복 일정, 외부 연동, 로그인

[요구사항 작성 전에 먼저 나에게 물어볼 것]
- priority를 프로토타입대로 높음/보통/낮음으로 갈지
(마감 저장 방식과 삭제 방식은 steering에서 이미 확정했으니 다시 묻지 말 것)
- "오늘 할 일"을 프로토타입처럼 TODO·DOING 전부로 할지
- 하고 싶은 일의 카테고리 목록
```

## Spec 2 프롬프트 초안 (Spec 1이 끝난 뒤 다듬어서 사용)

```
Spec 1의 task 기능 위에 편집 기능을 추가하고 싶어.
steering 문서와 product.md의 "편집 기능" 섹션을 따라줘.

[범위]
- 오늘 할 일: 제목, 우선순위, 마감 수정과 삭제
- 하고 싶은 일: 추가, 제목·카테고리 수정, 삭제, 카테고리 지정
- 우선순위 지정 (높음/보통/낮음)
- 편집은 모달로 하고, 기존 화면 배치는 바꾸지 마
- 모달 디자인은 docs/ 폴더의 모달 캡처 이미지(할 일 수정, 하고 싶은 일 추가·수정, 일정 추가·수정)를 그대로 따라줘
- 여는 방식: 행의 제목 영역 클릭 → 수정 모달, 하고 싶은 일 헤더의 + 버튼 → 추가 모달
- 하고 싶은 일에도 우선순위를 지정하고, "이번 주" 버튼으로 할 일이 되면 그 우선순위를 적용해줘

[참고]
- 삭제는 논리 삭제(deleted_yn)로 확정했어. steering의 db-conventions를 따라줘.
```

## Spec 3, 4는 앞 spec이 끝난 뒤에

앞 spec을 실행해 보면 steering에 보강할 규칙이 보입니다. 그때 steering을 먼저 고치고 다음 프롬프트를 쓰는 것을 추천해요.
